Collection Description
## EventHubAPI — End-to-End Test This collection validates the complete user journey through the EventHub API by executing a sequenced set of requests that mirror real-world usage — from account registration through event creation, booking management, and final cleanup. All requests are currently organized within the **Event Bookings Business Flow** folder and are intended to be run in order as a single collection run. To add more test flows (e.g. admin workflows, multi-user scenarios, or payment flows) can be added as separate folders following the same pattern. --- ### Notes: - A total of **9 failed test assertions** have been identified to date. - The identified failures are attributed to **BUG-001** and **BUG-005**, as documented in the **Bug Reports** collection. - The response time test assertion may fail when the response time exceeds **2,000 ms**. --- ### Current E2E Flow: Event Bookings Business Flow The flow executes the following steps in sequence: **1\. Authentication** - Register a new user account - Log in and capture the auth token - Verify the authenticated user's identity **2\. Event Management** - Create a new event - Retrieve the event by ID - Update the event (`BUG-001` regression) - Re-fetch the event after update to verify changes (`BUG-001`) - Delete the event - Confirm the event is no longer accessible **3\. Booking Management** - Create a booking for the event - Retrieve the booking by ID - Look up the booking by reference code - List all bookings (with pagination and optional status filter) - Create a booking at maximum ticket capacity - List all bookings again to verify state - Cancel a booking - Retrieve the cancelled booking by ID to confirm status - List all bookings filtered by `cancelled` status (`BUG-005` regression) --- ### Extensibility This collection is structured to support additional E2E flows. Suggested flows to add in future iterations: - **Admin / Organizer Flow** — event approval, capacity management, reporting - **Multi-User Booking Flow** — concurrent bookings from different user accounts - **Edge Case Flow** — overbooking attempts, invalid inputs, expired tokens - **Full Lifecycle Flow** — create → book → update → cancel → delete in one pass Add new flows as separate folders within this collection, following the same sequential execution pattern. ---
